# How to update the website

Everything on the site comes from a few text files in `content/` and a few images in `static/`.
You never edit HTML. Each time a change reaches the `main` branch on GitHub, the site is rebuilt
and published automatically, about one minute later, at <https://oliviercoulon.github.io/>.

Contents: [1. Where things are](#1-where-things-are) · [2. Two ways to edit](#2-two-ways-to-edit) ·

## 1. Where things are

| To change… | Edit |
|---|---|
| the publication list | `content/publications.bib` |
| the home page: statement, *Research* paragraph and facts, research themes and their key papers, projects, software | `content/home.yaml` |
| name, position, e-mail, phone, address, profile links (Scholar, ORCID, HAL, GitHub), institution logos | `content/site.yaml` |
| the sentence at the top of the contact page, the *About this site* notice | `content/contact.yaml` |
| the portrait | `static/img/portrait.jpg` |
| the figures of the research themes | `static/img/fig/` (and one line in `home.yaml`) |
| the logos | `static/img/logos/` |

Leave alone unless you want to change the design: `templates/`, `static/css/`, `static/js/`, `build.py`,
`.github/`. The folder `_site/` is generated by the build; it is never edited or committed.

## 2. Two ways to edit

### A. On github.com (simplest; good for text and publications)

1. Go to <https://github.com/oliviercoulon/oliviercoulon.github.io> and sign in.
2. Click your way to the file, for example `content` → `publications.bib`.
3. Click the **pencil** icon (*Edit this file*) at the top right of the file.
4. Make the change.
5. Click **Commit changes…**, write a short message (e.g. *Add Dupont et al. 2027*), keep
   *Commit directly to the main branch*, and confirm.
6. Open the **Actions** tab. The run *Build and deploy site* shows a yellow dot while it works, then a
   green tick (the site is online) or a red cross (nothing was changed online, see [section 5](#5-when-something-goes-wrong)).
7. Reload the site. If you still see the old version, force the reload (Cmd + Shift + R).

**Adding or replacing an image:** open the folder (e.g. `static/img/fig`), click **Add file → Upload files**,
drop the file and commit. A file uploaded with the same name as an existing one replaces it.

### B. On your computer (to see the result before publishing, or for many changes)

Once:

```bash
git clone https://github.com/oliviercoulon/oliviercoulon.github.io.git
```

```bash
cd oliviercoulon.github.io && pip install -r requirements.txt
```

Each working session, in the `oliviercoulon.github.io` folder:

```bash
git pull
```

```bash
python3 build.py --serve
```

Open <http://127.0.0.1:8150/>. After each edit, stop the command (Ctrl + C), run it again and reload the page.
The terminal lists warnings and the `[[...]]` placeholders still on the site.

To publish:

```bash
git add -A && git commit -m "Update home page" && git push
```

If you also edit on github.com, always `git pull` before starting, so that the two copies do not diverge.

## 3. Publications

The publication page is generated from `content/publications.bib`. Entries are sorted by year, then by their
order in the file, and numbered automatically (the most recent has the highest number). Your name is set in
bold automatically, and lists of more than 12 authors are shortened (first three … Coulon O … last author).
When an entry has a DOI, its title links to it and the DOI is written out under the reference; without a
DOI, the title links to the `url`, `hal_id` or `pdf` given in the entry, if any.

### Adding a publication

Paste the entry **anywhere** in the file. Three ways, from the quickest:

1. **DOI only.** Title, authors, journal, volume and pages are filled in from Crossref at each build:
   ```bibtex
   @article{dupont2027sulcal, doi = {10.1016/j.neuroimage.2027.120000}}
   ```
   Crossref gives the year of the printed issue, which can be a year after the online version. To choose the
   year yourself, add it: `@article{dupont2027sulcal, doi = {10.1016/...}, year = {2027}}`.
   If Crossref does not know the DOI yet (very recent papers), the entry is skipped, the site is still
   updated, and a warning appears on the Actions run. Wait a few days, or write the entry in full.

2. **Full BibTeX** copied from the journal page (*Cite* or *Export citation → BibTeX*), Google Scholar,
   Zotero or HAL. Or, in a terminal:
   ```bash
   curl -LH "Accept: application/x-bibtex" https://doi.org/10.1016/j.neuroimage.2015.02.008
   ```

3. **By hand**, for an entry without a DOI:
   ```bibtex
   @inproceedings{coulon2027isbi,
     author    = {Coulon, Olivier and Auzias, Guillaume},
     title     = {Title of the paper},
     booktitle = {IEEE International Symposium on Biomedical Imaging (ISBI)},
     address   = {City, Country},
     year      = {2027}
   }
   ```
   Common types: `@article` (with `journal`), `@inproceedings` (with `booktitle`), `@incollection` (book
   chapter, with `booktitle` and `publisher`), `@misc` (preprint, with `journal = {bioRxiv}`).

The **key** (the word right after `{`) must be unique and without spaces. The convention used in the file is
first author + year + first word of the title, e.g. `dupont2027sulcal`. The home page refers to papers by
this key.

### Optional fields

| Field | Effect |
|---|---|
| `keywords = {selected}` | star ★, and listed under the *Selected* filter |
| `keywords = {preprint}` | *Preprint* tag (automatic when the journal is bioRxiv, medRxiv or arXiv) |
| `keywords = {selected, preprint}` | both |
| `note = {* co-first authors}` | short note shown after the reference |
| `pdf = {https://…}` | *PDF* link |
| `hal_id = {hal-01234567}` | *HAL* link |
| `code = {https://github.com/…}` | *Code* link |
| `url = {https://…}` | *Link*, shown only when there is no DOI |

### Other common changes

- **A preprint is published:** replace the entry with the published one (or change `journal` and `doi` and
  remove `preprint` from `keywords`). Keep the same key, so that the home page keeps pointing to it.
- **Select or unselect a paper:** add or remove `selected` in `keywords`.
- **Accents:** type them directly (é, ü, ç) or in LaTeX (`{\'e}`); both work.
- **Remove a publication:** delete the whole entry, from `@` to its closing `}`. If its key appears in
  `home.yaml` (key papers of a theme, software), remove it there too.
- Lines starting with `%` are comments. The `.bib` file can be downloaded from the publication page, so
  do not write private notes in it.

## 4. Home page and other pages

`home.yaml`, `site.yaml` and `contact.yaml` are YAML files. A few rules:

- **Indentation matters.** Use spaces, never tabs, and keep the same indentation as the neighbouring lines.
- Put a text in **double quotes** if it contains `: ` or starts with `[`, `{`, `*` or `#`.
- `>-` starts a text written over several lines; the lines are joined into one paragraph.
- `|` keeps the paragraphs: leave an empty line between two paragraphs (used for the *Research* text).
- Links are written in Markdown: `[MeCA](https://meca-brain.org)`.
- `[[...]]` marks text still to be written. It is shown in yellow on the site. Delete the brackets and
  their content when done.

### Recipes

**Key papers of a theme** (`home.yaml`, under `themes`): list BibTeX keys,
```yaml
    papers: [auzias2015deep, auzias2016marsatlas, leguen2017genetic]
```

**Figure of a theme.** Upload the image to `static/img/fig/` (PNG or JPG, about 1200 px wide; the frame is
4:3 landscape and the whole image is always shown; a click opens it at full size). In `home.yaml`, the
`figure:` line of the theme reads:
```yaml
    figure: {image: img/fig/CS-folding.png, caption: "Parameterisation of the left and right central sulcus", white: true}
```
To change the figure, upload the new image and change the file name (and the caption). `white: true` puts the
image on a white background (without it: black, suited to MRI). The caption is shown when the mouse is over the
figure and serves as the image description.

**Project** (`home.yaml`, under `projects`): copy the BaboFet block, from `- name:` to `url_label:`, and
adapt it. `logo` (an image in `static/img/logos/`) and `url` are optional.

**Software or resource** (`home.yaml`, under `software`): copy a block of four lines (`name`, `what`,
`papers`, `url`). `papers: []` if there is no paper.

**Facts next to the Research text** (Position, Team, Institute, Career, Keywords):
`- {label: Career, text: "..."}` lines under `about: facts:`.

**Number of recent publications** on the home page: `recent_count` at the end of `home.yaml`.

**Profile links** (`site.yaml`, under `profiles`): one line per link; delete a line to remove a profile, copy
one to add a profile. The home page, the contact page and the footer change together.

**Portrait:** replace `static/img/portrait.jpg`, keeping that name. Take a photo of at least 400 × 400 px,
with the face centred in the upper part. It is shown as a grey-scale circle.

**Sentence at the top of the contact page** (`contact.yaml`): `intro: "..."`, or `intro: ""` for none.

## 5. When something goes wrong

- **Red cross in Actions.** The build stopped and the online site has **not** changed. Click the run, then the
  *build* job: the message names the file and the line, for example
  `content/publications.bib, line 412: cannot read the entry '@article{dupont2027,'` (usually a missing `}`),
  or `content/home.yaml is not valid YAML` (indentation or quotes). Fix the file and commit again.
- **Yellow warnings** on the summary page of a run. The site was updated, but something needs a look: a DOI
  that Crossref does not know, a key cited in `home.yaml` that is not in the `.bib` file, a duplicate key,
  or `[[...]]` placeholders still on the site.
- **Undo a change.** On github.com, open the file, click **History**, open the previous version and copy its
  content back into the file. Locally: `git revert <commit>`, then `git push`.
- **Green tick but old page.** GitHub caches pages for up to 10 minutes; force the reload (Cmd + Shift + R).

## 6. Good to know

- The repository is public: GitHub Pages serves public repositories with a free account, so everything in it
  can be read.
- Colours and layout are in `static/css/style.css`, the page structure in `templates/`.
- The BaboFet project site is a separate repository, to be published at <https://oliviercoulon.github.io/babofet/>.
  Until it is online, the three links to it are commented out in `home.yaml` (lines marked *BaboFet site not
  online yet*): remove the `#` of those lines once the BaboFet site works.
- `tools/import_oldsite.py` imported the publication list of the former Google Sites page on 2026-11-24.
  It is kept for reference and will not overwrite an edited `publications.bib` without `--force`.
